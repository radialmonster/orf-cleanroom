# SPEC: V2 (large-sensor compressed ORF payloads, not understood)

Stub. Assembled only from verified findings and open leads. A statement that cites only a lead is **unverified** and marked so. No decoder exists for V2; the reference decoder reports "not yet specified". Definition: [VARIANTS.md](../VARIANTS.md#v2-large-sensor-compressed-not-understood). Compare [V1.md](V1.md).

## S1. Verified
Nothing yet. No finding is specific to V2. Container facts that apply (compression tag 1 on every file; fixed-size payloads told by exact size, so compressed means variable size) are in [V0.md](V0.md) S1.

## S2. Lead only (unverified)
- S2.1 On four large-sensor CC0 files (ids 7267, 7269, 7801, 7803) the #11 parse gives tokens per pixel within 0.3% to 2.1% of an independent-bits null, so the ordinary code does not fit it. [lead #86, unverified]
- S2.2 The earlier statement that these files share a 31-bit escape is not established. Lead #37 found no q=30 escape in 11 CC0 files (escapes at q 17 to 29). Measured on 15 CC0 compressed files (tools/orf_tokens.py, first 1.5 to 3 million tokens; ids 1993, 1994, 1995, 1996, 3801, 6343, 8549, 8552 and the large-sensor ids 3573, 5284, 7265, 7267, 7269, 7801, 7803): escapes (q >= 17) fall at q 17 to 28, most at 17 to 21 and falling after; the rest are isolated (q 31 once, 32 twice; q 47 once in each of the four largest files and q 39 once in each of the other eleven, probably the zero fill at the end of the payload). There is no peak at q 30 or 31, and the distance at which the stream resynchronises after an escape (--escape-landing) does not single out a 31-bit word. So a 31-bit escape is not established by public measurement. [lead #37 and an inventory run, unverified]

## Gaps
- G1. **Larger sensors:** the ordinary (non-escape) code in these files. Code-length statistics on larger-sensor files, compared with V1, would constrain it. What follows a long zero run (escape) and how many bits it takes is open (S2.2).
- G2. **V2 classification:** which compressed manifest files belong to V2, or to some further variant, is not settled (their `variant` stays `unassigned`). To test: define a signature (payload width, bits per pixel, escape behaviour) in a `tools/` script, run it over all CC0 manifest files, and report which files it separates and how strongly.
- G3. Hypothesis H1 (one shared compression scheme, V2 reducing to V1 under some parameter) is listed in [V1.md](V1.md) G6 (hypothesis, unverified).
