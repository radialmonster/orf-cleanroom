# SPEC: V0 (fixed-size, uncompressed ORF payloads)

Assembled only from verified findings and open leads. Every statement cites its source. A statement that cites only a lead is **unverified** and marked so. The reference implementation is `decoder/orf_decode.py`; its output hashes are in `samples/conformance-V0.csv`. This spec changes by new findings, never by edit-in-place guesses: when a lead is verified, replace its citation here by the finding ID in a PR.

## S1. Recognising V0 (container)
- S1.1 The TIFF compression tag is 1 on every ORF seen, compressed or not, so it does not tell V0 from anything else. [F-tag]
- S1.2 A payload is V0 exactly when its byte count equals width x height x 12, 12.8 or 16 bits / 8 (`size_class` packed-12, packed-12.8, packed-16). Any other size is "variable" (compressed, V1 and later, not specified here). [F-fixed]
- S1.3 The payload is the set of raw-image strips of the IFD with the largest strip byte total; strips are read in StripOffsets order and concatenated. On 6 of the 9 packed-12 CC0 files there is one gap between strips (1224 to 1624 bytes), so strips must be read individually, not as one contiguous run. The concatenation then equals height x row bytes exactly. [F-layout, partial: measured strip geometry and exact totals on the 17-file cohort; general gap rules remain open, G1]
- S1.4 Row layout on the measured cohort: the 6 packed-12 files with the strip gap support two-field storage, with stored rows 0..n1-1 (n1 = ceil(h/2)) corresponding to even image rows and stored rows n1..h-1 to odd rows; the gap and a stored-row discontinuity occur at n1. Interleaving restores distance-two row continuity over every eligible interior row of the 400 centre columns. The other 11 files support natural order. [F-layout, partial: same files, wider row coverage, not a new body or proof of absolute physical row origin] The decoder chooses layout by comparing stored rows 1 apart with 2 apart; its general selector remains unverified (G1, G6; lead #77 remains open).

## S2. packed-12
- S2.1 Two 12-bit values per 3 bytes, most significant bit first: first = b0 << 4 | b1 >> 4, second = (b1 & 15) << 8 | b2. Rows are contiguous with stride width x 1.5 bytes. [F-p12]
- S2.2 Six bodies (C5060WZ, C7070WZ, SP-510UZ, SP-550UZ, SP-565UZ, SP-570UZ) use this order directly. Three (XZ-2, XZ-10, SH-2) first have the bytes reversed inside every 4-byte word. [F-p12]
- S2.3 Which of the two applies is chosen by smoothness of the unpacked values (the finding's method); there is no header field known to say. The decoder picks the order with the lower roughness on 3 bands of 16 rows. [F-p12; decoder choice]
- S2.4 The order of the two pixels inside a unit is NOT decided by the evidence. The reference decoder emits first, second. Output hashes therefore pin this choice. [F-p12, last sentence of its claim]
- S2.5 Observation (partly a finding, see F-hdr): all 6 plain files have header `IIRS`, all 3 reversed ones `IIRO`. [decoder run; whole-frame pairing header to byte order and strip gap holds on 9 of 9 CC0 files (6 `IIRS` plain, F-hdr; 3 `IIRO` reversed, 1 in F-hdr and XZ-10, SH-2 in F-iiro, roughness reversed 0.025 to 0.058 against plain 0.590 to 0.806 on the two) and 4 of 4 non-CC0 `IIRS` files, F-hdr (partial) and F-iiro (partial); same files as lead #78, so no new body; the rule itself stays a candidate, confounded with camera generation; header versus strip table is not separated; lead #78 open; see gap G2]

## S3. packed-12.8
- S3.1 Rows are runs of 16-byte groups, 10 pixels per group. Bytes 0 to 14 are five 3-byte units; each unit holds two 12-bit values least significant bit first: first = b0 | (b1 & 15) << 8, second = b1 >> 4 | b2 << 4. Byte 15 is padding. Rows are contiguous, stride width x 1.6 bytes. [F-p128] Width is a multiple of 10. [observation on the 5 files]
- S3.2 Byte 15 is 0 in every group of the whole payload on all 5 CC0 files, and each payload is exactly width x height x 1.6 bytes, a whole number of groups. [F-p128] The decoder still reports the count of non-zero pad bytes.
- S3.3 The order of the two pixels inside a unit is not decided (tie within 2%); the decoder emits first, second. [F-p128; gap G4]

## S4. packed-16
- S4.1 One 16-bit word per pixel holding the 12-bit value shifted left by 4; stride width x 2. [F-p16] On the three CC0 files the payload is exactly width x height x 2 bytes, their strips are contiguous, and whole-frame lag-2 roughness jumps at one byte off the true stride (0.064 / 0.641 / 0.642 on E-1, 0.039 / 0.663 / 0.663 on E-400, 0.046 / 0.753 / 0.746 on E-10 at 0 / -1 / +1 byte). [F-p16]
- S4.2 Byte order is per body: E-1 and E-400 little-endian, E-10 big-endian. [F-p16] Whole-frame smoothness (little-endian against big-endian roughness) agrees with the TIFF byte-order mark on 3 of 3: E-1 0.126 against 1.414 and E-400 0.078 against 1.409 (`II`, little-endian smoother), E-10 1.661 against 0.090 (`MM`, big-endian smoother), margins 11.2 to 18.4 [F-p16; the same three files were measured whole-frame in F-iiro, Partial]. E-10 is the only `MMOR` file, so the mark and the file header are not separated. The rule stays a candidate (gap G2). The decoder still autodetects by smoothness.
- S4.3 Output hashes use the stored words, not shifted back. On E-400, 793 words have a non-zero low nibble; E-1 and E-10 have none. 791 of the 792 interior ones equal the floor of the mean of the 4 nearest same-colour neighbours: diagonal-1 at parities (0,0) 218 and (1,1) 187, axial-2 at (0,1) 183 and (1,0) 203, so the stored words are interpolated pixels. [F-e400, partial verification of lead #79; the 793 whole-frame count is confirmed in F-p16; one exception, gap G3]

## S5. Not specified
Everything else (V1, V2, all compressed payloads) is "not yet specified". The reference decoder reports that and decodes nothing.

## S6. Output hash (conformance)
SHA-256 of the decoded values as little-endian uint16, row-major in image row order (S1.4 undone for two-field files), unshifted (no shift applied by the decoder: packed-16 words are hashed as stored, low nibbles included, S4.3), width x height values. Two implementations agree on a file when this hash matches. A second implementation written from this spec alone matches all 17 hashes with exact payload ends [`2026-10-19--radialmonster--independent-v0-hash-agreement` (findings/V0), partial verification of lead #75]. It used the explicit selectors of G6 (header, strip-gap position, TIFF byte-order mark), so on these 17 files those rules and the smoothness choices agree.

## S7. Synthetic envelope stress test
The frozen toy development envelope accepts 7/9 identity `floor(stored_word/16)` windows and 16/36 nonidentity controls across the three public CC0 packed-16 files, with two identity rejections. This is a bounded construction-label stress test under the stated scale assumption; it does not establish a correct sensor mapping, physical plausibility, or a decoding rule. The three files and all nine windows are the complete current CC0 packed-16 manifest cohort. [F-toy]

## Gaps (each is a lead to open)
- G7. packed-12.8 and packed-16 black level and saturation per body (carried from lead #70 and the closed lead #71): not measured. Also any packed-12.8 or packed-16 file from a body other than the CC0 ones (for packed-16: E-1, E-400, E-10) would test the rules on a new body.
- G8. Synthetic envelope sensitivity to larger windows and additional lawful CC0 files: lead #325 tested the frozen 32x24 windows on the complete current three-file CC0 packed-16 cohort. Measure larger windows and preserve the current rejected identity windows as controls.
- G9. Physical plausibility of candidate packed-16 mappings: establish noise, black level, effective precision and CFA assumptions from lawful controlled data before assigning physical-plausibility labels. The construction-label result in F-toy does not settle these assumptions.
- G10. Independent held-out evaluation of the toy envelope: test genuinely held-out body, mode, exposure or scene groups. The nine windows in F-toy are not independent groups.
- G1. General strip-gap/layout selector (S1.3, S1.4): F-layout verifies the gap position, discontinuity and exact strip byte totals on the original 17-file cohort. In all six two-field files, the split is both ceil(h/2) and the gap position, so these candidate rules are not separated. To test: an additional IIRS packed-12 input/body, or a file where gap position and ceil(h/2) disagree; report the geometry and row-continuity scores. Physical row origin and generalization beyond the cohort remain open in lead #77.
- G2. Header byte order ties (S2.5, S4.2). Packed-16 byte order versus the TIFF byte-order mark: E-1 and E-400 (`II`, little-endian) and E-10 (`MM`, big-endian) agree with the mark, 3 of 3. That cannot separate a rule from chance. To test: any packed-16 file from another body; report the mark and which order is smoother. Header `IIRS` vs `IIRO` on packed-12 separates the layouts 9 of 9 (lead #78; F-hdr and F-iiro re-ran all 9 CC0 files whole-frame, not a new body) but is confounded with camera generation. The packed-16 whole-frame run is F-iiro and F-p16 (3 of 3, same files). Still untested: a packed-12 or packed-16 file from a body outside the CC0 set, and whether the header or the strip table decides (every file has both; an `IIRO` file with a strip gap or an `IIRS` file without one would separate them).
- G3. E-400 low nibble (S4.3; floor-mean rule verified on one file, F-e400): one interior word (y 2585, x 3681) matches neither family; its diagonal neighbour (y 2586, x 3680) has low nibble 15, the only interior nibble outside 4, 8 and 12. (The earlier note that no other (1,1) word matches came from a transcription slip in lead #79: 187 do.) To test: a second E-400 file or another E-series packed-16 body; does the exception come from a mapped neighbour, and does the defect list repeat between files? Note `tools/e400_probe.py` reads little-endian only, so use the decoder for E-10 (`MM`).
- G4. Pixel order inside a packed-12 unit (S2.4) and inside a 12.8 unit: first-then-second (as emitted by the reference decoder) or swapped. Numbers so far, from `tools/unit_order_probe.py` on 14 CC0 files (packed-12 and 12.8): ratio A/W of the cross-unit to the within-unit lag-1 difference is 0.997 to 1.001 (all rows) for the emitted order and 1.000 to 1.063 for the swapped one; on edge-rich units only (threshold 300) emitted 0.97 to 1.08, swapped 1.004 to 1.278, and the swapped order is never smoother than the emitted one. This is in the right direction on every file but within 0.1 to 0.5% on 5 of the 14 (XZ-10, SH-2, SP570UZ, XZ-2, SP565UZ), so it is not decisive. To test: a file with a hard, sharp, vertical edge or a chart with fine horizontal detail (large cross-unit differences), or a derived relation between the two pixels of a unit and the known CFA colours (the pair must be R,G or G,B in that order across the row).
  On all stored rows at threshold 300, 2856 gives emitted/swapped ratios 1.005099/1.169864; predeclared 2977 gives 1.001874/1.016390. These use the reference unpacking and do not establish physical order. [F-unit-whole] Follow-up to #538: seek independent evidence linking the metric to physical pixel order; #75 remains open.
- G5. Hypothesis H2, High Res Shot files need separate handling (hypothesis, unverified; not evidence). Source: vendor documentation that the mode exists. It is not V0-specific: of the 21 High Res Shot files in the manifest, 2 (PEN-F, E-M5 Mark II) are packed-12.8 (VARIANTS.md) and 19 are compressed; it is kept here because the only evidence so far is the V0 pair and the ID H2 is already cited, and V1.md G7 points back here. To test: measure their signature; if they differ, propose a new V<n> as a lead.
- G6. Layout selectors are not fully specified (S1.4, S2.3, S4.2). The two-field test, the plain/reversed choice and the packed-16 byte order are each defined here only as "by smoothness", and the exact scoring (bands, rows compared, aggregation, ties) exists only in the reference decoder. So an implementation written from this spec alone cannot reproduce those choices exactly. Candidate explicit rules: header `IIRS`/`IIRO` for S2.3 (lead #78; F-hdr, F-iiro, both Partial), the strip-gap position at stored row n1 for S1.4 (F-layout, Partial; lead #77 stays open), and the TIFF byte-order mark for S4.2 (G2; F-iiro, Partial). The blind implementation's agreement on all 17 hashes (S6) establishes agreement of the explicit and smoothness choices on this cohort, not general selectors. To test: compare on any further V0 file, or pin one rule per selector here once a lead verifies it.
