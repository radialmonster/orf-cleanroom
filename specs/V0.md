# SPEC: V0 (fixed-size, uncompressed ORF payloads)

Assembled only from verified findings and open leads. Every statement cites its source. A statement that cites only a lead is **unverified** and marked so. The reference implementation is `decoder/orf_decode.py`; its output hashes are in `samples/conformance-V0.csv`. This spec changes by new findings, never by edit-in-place guesses: when a lead is verified, replace its citation here by the finding ID in a PR.

IDs used below:
- `F-fixed` = `2026-10-19--radialmonster--fixed-size-payloads-exact-else-compressed` (findings/container)
- `F-tag` = `2026-10-19--radialmonster--compression-tag-is-1-on-every-orf` (findings/container), reproduced by `2026-10-19--radialmonster--compression-tag-independent-reproduction`
- `F-p12` = `2026-10-19--radialmonster--packed-12-msb-two-values-per-three-bytes` (findings/V0)

## S1. Recognising V0 (container)
- S1.1 The TIFF compression tag is 1 on every ORF seen, compressed or not, so it does not tell V0 from anything else. [F-tag]
- S1.2 A payload is V0 exactly when its byte count equals width x height x 12, 12.8 or 16 bits / 8 (`size_class` packed-12, packed-12.8, packed-16). Any other size is "variable" (compressed, V1 and later, not specified here). [F-fixed]
- S1.3 The payload is the set of raw-image strips of the IFD with the largest strip byte total; strips are read in StripOffsets order and concatenated. On 6 of the 9 packed-12 CC0 files there is one gap between strips (1224 to 1624 bytes), so strips must be read individually, not as one contiguous run. The concatenation then equals height x row bytes exactly. [observation on the 17 CC0 files from the decoder run; NOT a finding yet, see gap G1]
- S1.4 Row layout (UNVERIFIED): the 6 packed-12 files with the strip gap store their rows as two fields: stored rows 0..n1-1 (n1 = ceil(h/2)) are the even image rows, stored rows n1..h-1 the odd image rows, and the gap falls at stored row n1. The other 11 files are in natural order. The decoder detects this by comparing stored rows 1 apart with 2 apart. [lead #77, unverified; this also settles why strips must be read individually, gap G1]

## S2. packed-12
- S2.1 Two 12-bit values per 3 bytes, most significant bit first: first = b0 << 4 | b1 >> 4, second = (b1 & 15) << 8 | b2. Rows are contiguous with stride width x 1.5 bytes. [F-p12]
- S2.2 Six bodies (C5060WZ, C7070WZ, SP-510UZ, SP-550UZ, SP-565UZ, SP-570UZ) use this order directly. Three (XZ-2, XZ-10, SH-2) first have the bytes reversed inside every 4-byte word. [F-p12]
- S2.3 Which of the two applies is chosen by smoothness of the unpacked values (the finding's method); there is no header field known to say. The decoder picks the order with the lower roughness on 3 bands of 16 rows. [F-p12; decoder choice]
- S2.4 The order of the two pixels inside a unit is NOT decided by the evidence. The reference decoder emits first, second. Output hashes therefore pin this choice. [F-p12, last sentence of its claim]
- S2.5 Observation, not a finding: all 6 plain files have header `IIRS`, all 3 reversed ones `IIRO`. [decoder run; see gap G2]

## S3. packed-12.8 (UNVERIFIED)
- S3.1 Rows are runs of 16-byte groups, 10 pixels per group. Bytes 0 to 14 are five 3-byte units; each unit holds two 12-bit values least significant bit first: first = b0 | (b1 & 15) << 8, second = b1 >> 4 | b2 << 4. Byte 15 is padding. Width is a multiple of 10. [lead #70, unverified]
- S3.2 Whether byte 15 is always 0 is a next step of #70; the decoder reports the count of non-zero pad bytes. [lead #70]

## S4. packed-16 (UNVERIFIED)
- S4.1 One 16-bit word per pixel holding the 12-bit value shifted left by 4; stride width x 2. [lead #71, unverified]
- S4.2 Byte order is per body: E-1 and E-400 little-endian, E-10 big-endian. [lead #71, unverified] Observation: E-10 is the only `MMOR` file and the other two are `II`, so byte order matches the TIFF header on 3 of 3 (gap G2). The decoder still autodetects by smoothness.
- S4.3 Output hashes use the stored words, not shifted back. On E-400, 793 words have a non-zero low nibble; E-1 and E-10 have none. Unexplained (gap G3).

## S5. Not specified
Everything else (V1, V2, all compressed payloads) is "not yet specified". The reference decoder reports that and decodes nothing.

## S6. Output hash (conformance)
SHA-256 of the decoded values as little-endian uint16, row-major in image row order (S1.4 undone for two-field files), unshifted, width x height values. Two implementations agree on a file when this hash matches.

## Gaps (each is a lead to open)
- G1. Strip-gap rule (S1.3; the layout lead #77 now explains where the gap falls, stored row n1): a smoothness check across the gap does not discriminate (same numbers whether the gap is skipped or read through), so the rule rests on TIFF StripOffsets semantics and exact byte totals only.
- G2. Header byte order ties (S2.5, S4.2).
- G3. E-400 low nibble (S4.3).
- G4. Pixel order inside a packed-12 unit (S2.4) and inside a 12.8 unit.
